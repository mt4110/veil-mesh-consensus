## 製品の今回のゴール

**対応を確認した一つのLinux環境で、小規模公開サイトの運用者が、既知の送信元IPv4一件を、専用の宛先IPv4・TCP portに限って有限時間遮断し、安全に解除・停止・復旧できる。導入先・制約・操作手順・証拠が揃い、限定的な試験導入に使える。**

これは既存のローカル一時BANの契約を具体化したもの。自動攻撃検知、BFTの再開、複数サイト・全protocol・回線飽和対策、大規模運用の保証を今回の完了条件に追加しない。OSSとしての提供方針を維持し、販売や収益を合格条件にしない。

## 合格に必要な六つの確認

| 条件 | 必要な証拠 |
| --- | --- |
| 正常に届く | 宣言した公開経路でHTTPSの証明書・期待body・実送信元を確認。proxyやNATの変換後tupleを記録 |
| 対象だけ止まる | 一件BANの実遮断とkernel counter差。同じXDP入口・同じ保護tupleの独立正常client、管理通信、対象外通信が継続 |
| 明示解除できる | 新しいpreviewとinstance／revisionで、元の期限が来る前に解除し、対象通信の復帰を確認 |
| 自動で失効する | 別の有効な一時BANが元の有限TTLで失効して通信復帰。期限の延長・再BANで代用しない |
| 再起動・停止から戻る | 承認した通常daemon restartでBAN0・新instance、旧操作拒否、通信復帰。停止後は所有XDP非装着 |
| 運用・保全が成立する | 本人が対象・一覧・preview・実適用・解除・結果不明時の判断を確認できる。復旧手順・制約・検証範囲を記録し、既存データ・他サービスを保全 |

256／257件境界、SIGKILL、所有記録破損等の障害注入は新hostの隔離環境で確認し、公開siteへ持ち込まない。既存証拠を再利用できるのは同じ成果物・条件の範囲だけで、新しいVMのkernel／NIC対応を自宅の成功から転記しない。

公開証明書・独立正常client等が未確定なら、その未確認を残す。自前CAを明示信頼した試験を、普通のブラウザの既定信頼での公開運用成功と同一視しない。

六条件が揃えば、その確認した環境を「限定試験導入候補」と判定する。実際の対象siteのtuple、基礎防御、TLS、復旧担当を[導入前チェックリスト](PILOT_CHECKLIST.md)へ記入し、配備は具体的な変更承認後に行う。

## 試験の順序と上限

| 段階 | 目的・上限 | 次へ進む条件 |
| --- | --- | --- |
| 自宅の追加WAN試験 | 準備・承認待ちを含む30分以内、最大1回。従来どおり一件BAN・明示解除まで | 成功でも失敗でも自宅の追加試行は終了。認証・helper不備による中止も一回と数える |
| クラウド環境の適合確認 | まずroot Linux VMのkernel／実ingress／XDP装着・解除・管理復旧を確認。非対応なら試験サービスを公開しない | 対応と復旧が確認でき、費用・対象・許可範囲への承認がある |
| VMでの受入れセッション | 新規VM最大2台・最大4時間を費用見積りの案とする。上の六条件と隔離検証を一つの計画にまとめる | 固定した各caseを一度ずつ実施。原因不明の同条件反復をしない。失敗修正後の再実行は範囲・残予算を改めて判断 |

自宅の成功はVM開始の条件ではない。準備が整わず自宅を開始できない場合も、ルーター操作を反復せず、本人に状況を示してVM準備へ移る。自宅試験の上限をVMの名目で延長しない。

VMの4時間は新規の費用・作業枠の提案であり、まだ確定していない。サービスの180秒／240秒やTTLを4時間へ延ばす意味ではない。解除・自然失効・通常restartには、それぞれ独立した短いcaseと必要な承認を用意し、以前の「BAN一回」の承認を流用しない。

試験の上限到達は作業を打ち切る条件であり、製品の合格ではない。上限後も必要な安全な復旧は行うが、追加試験はしない。未達のcaseが残れば、その環境での製品ゴールは未達と明記する。

## 終了時の判断

「試験した」「28件通った」「二環境で動いた」だけを最終判定にしない。六条件と導入先の実構成に対し、**環境名・成果物hash・合格case・未確認・復旧結果・推奨可否**を一枚にまとめる。

自宅未確認でもVMで条件を満たせば、確認したVM構成を試験導入候補にできる。自宅対応は未確認のまま残す。両方とも条件を満たせなければ、製品ゴール未達として止め、機能追加・試験追加を自動で続けない。

技術的な合格とは別に、手動BANが役立つ具体的な運用場面と既存のfirewall／Cloudflare等との差を本人の試用で判断する。不要なら採用しない。この判断を無限の追加実装へ置き換えない。
